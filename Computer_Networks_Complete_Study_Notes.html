MODULE 1 — Introduction to Data Communications, Network Models, Physical Layer & Switching

💡 ELI5 (Explain Like I'm 5): What is a Computer Network?
Imagine you and your best friend live across the street and want to talk without yelling. You connect a string between two tin cans (Physical Medium). When you speak (Sender), your voice makes vibrations (Message) that travel across the string to the friend's can (Receiver). But wait! What if you speak English and your friend only speaks Spanish? You won't understand each other! You must both agree on rules: "We will both speak English, one person talks at a time, and we say 'Over' when finished." Those agreed rules are called the Protocol. A computer network is just millions of computers doing this across the entire world!

1. Introduction to Data Communications (Ch. 1.1)

Data Communications is the exchange of data between two devices via some form of transmission medium (such as a wire cable or wireless radio waves). For data communication to be effective, the system must deliver data to the correct destination (Delivery), accurately without alterations (Accuracy), in a timely fashion without significant jitter (Timeliness), and with minimal variation in packet arrival times (Jitter).

1.1 Five Fundamental Components of Data Communication

Fig 1.1: The Five Fundamental Components of Data Communication
  • 1. Message: The information (data) to be communicated. Popular forms include text, numbers, images, audio, and video.
  • 2. Sender: The device that creates and sends the data message (e.g., computer, smartphone, video camera).
  • 3. Receiver: The device that receives the message (e.g., workstation, server, printer, television).
  • 4. Transmission Medium: The physical path by which a message travels from sender to receiver (e.g., twisted-pair wire, coaxial cable, fiber-optic cable, or radio waves).
  • 5. Protocol: A set of formal rules that govern data communications. It represents an agreement between communicating devices; without a protocol, two devices may be connected, but cannot communicate (like two humans who speak different languages).

1.2 Data Representation & Data Flow

Information today comes in various digital formats:

  • Text: Represented as bit patterns using standard codes such as ASCII (7-bit), Unicode (UTF-8, UTF-16, UTF-32) allowing representation of symbols in any language.
  • Numbers: Converted directly to binary numbers for arithmetic processing.
  • Images: Represented as a matrix of pixels. Each pixel is assigned a bit pattern representing color and intensity (e.g., RGB 24-bit true color).
  • Audio & Video: Continuous analog signals converted into digital streams through sampling and quantization (PCM). Video is a sequence of continuous picture frames.

Direction of Data Flow: Simplex, Half-Duplex, and Full-Duplex

2. Networks and Network Types (Ch. 1.2 & 1.3)

A Network is a set of devices (often referred to as nodes or hosts) connected by communication links. A node can be a computer, printer, switch, router, or any other device capable of sending and receiving data.

2.1 Network Criteria

  • Performance: Measured in terms of Throughput (actual data delivered successfully per unit time, bps) and Delay / Latency (time taken for a message to travel from sender to receiver, including propagation time, transmission time, queuing delay, and processing delay).
  • Reliability: Measured by frequency of failure, the time it takes to recover from a failure (MTTR — Mean Time To Repair), and the system's robustness in a catastrophe.
  • Security: Protecting data from unauthorized access, damage, viruses, and implementing data integrity and privacy policies.

2.2 Physical Structures & Topologies

A network is defined by its type of connection and its physical topology:

  • Point-to-Point Connection: Provides a dedicated link between two devices. The entire channel capacity is reserved for transmission between those two endpoints.
  • Multipoint (Multidrop) Connection: A single communication link is shared simultaneously or in time-sharing mode by more than two devices.

2.3 Network Categories (LAN, MAN, WAN)

  • Local Area Network (LAN): Spans a small geographical area (an office, home, or university campus). Usually privately owned, operates with high data rates (100 Mbps to 10 Gbps) and very low error rates.
  • Metropolitan Area Network (MAN): Spans an entire city or town (e.g., cable television network across a city).
  • Wide Area Network (WAN): Provides long-distance transmission over large geographic areas (countries, continents). Typically comprised of:
    • Point-to-Point WAN: Connects two specific communication devices through a leased line or transmission provider.
    • Switched WAN: A network connecting multiple end nodes through a mesh of packet/circuit switches (e.g., Asynchronous Transfer Mode - ATM, Frame Relay, or the core Internet).
  • Internetworks (The Internet): An interconnection of two or more independent networks joined by internetworking devices (routers and gateways).

3. Network Models: Protocol Layering & OSI vs TCP/IP (Ch. 2.1 - 2.3)

💡 ELI5: Why do we use Protocol Layering? (The Postal Service Analogy)
When you write a letter to your friend in another country: 1. Application Layer: You write your message on paper. 2. Packaging: You put it in an envelope and write the name and address. 3. Local Post Office: Sorts the mail and decides the route. 4. Transport / Cargo Flight: Flies the mail bag across oceans. The airplane pilot doesn't need to read your letter or understand English! The pilot only cares about flying the cargo bag. Layering creates modular independence: each layer solves one specific job and trusts the layer below it.

3.1 Principles of Protocol Layering

  • Modularity: Complex communication tasks are divided into smaller, self-contained sub-tasks.
  • Explicit Interfaces: Each layer provides well-defined services to the layer immediately above it and receives services from the layer below it.
  • Independence: An implementation at one layer can be swapped out (e.g., changing from Wi-Fi to Ethernet) without breaking the higher application layers.
Fig 1.3: Comparison of the 7-Layer OSI Reference Model and 5-Layer TCP/IP Suite with PDUs

3.2 The 7-Layer OSI Reference Model

Developed by the International Organization for Standardization (ISO). From bottom to top:

  1. Layer 1 — Physical Layer: Transmits raw bits over a physical transmission medium. Defines mechanical, electrical, and functional specifications (voltage levels, pin layouts, bit timing, data rates).
  2. Layer 2 — Data Link Layer (DLL): Transforms an unreliable raw physical transmission facility into a reliable link. Groups bits into Frames. Handles physical (MAC) addressing, error detection & correction, flow control, and access control.
  3. Layer 3 — Network Layer: Responsible for source-to-destination delivery of individual Packets across multiple networks. Provides logical addressing (IP addresses) and Routing (choosing the best path through intermediate routers).
  4. Layer 4 — Transport Layer: Provides end-to-end (process-to-process) communication. Breaks application messages into Segments, assigns sequence numbers, manages flow control, error recovery, and port addressing (multiplexing/demultiplexing).
  5. Layer 5 — Session Layer: Establishes, manages, and terminates communication sessions between applications. Provides dialog control (half-duplex/full-duplex) and synchronization checkpoints.
  6. Layer 6 — Presentation Layer: Handles the syntax and semantics of the information exchanged. Responsible for Translation (character encoding like ASCII/Unicode), Encryption/Decryption (security), and Compression.
  7. Layer 7 — Application Layer: Provides interfaces and protocols directly to user applications and network services (HTTP, FTP, SMTP, DNS).

3.3 The 5-Layer TCP/IP Protocol Suite

The commercial Internet was built on the TCP/IP protocol suite. In TCP/IP, the Session and Presentation functions are handled within the Application layer itself, yielding a streamlined 5-layer model: Application, Transport, Network (Internet), Data Link, and Physical.

🔑 Addressing in the TCP/IP Protocol Suite (Crucial for Exams)
Four distinct levels of addresses are used across the TCP/IP layers:
  • 1. Physical (MAC) Address: 48-bit hardware address (e.g., 00:1A:2B:3C:4D:5E) used by the Data Link Layer to deliver frames within the same local network link.
  • 2. Logical (IP) Address: 32-bit (IPv4) or 128-bit (IPv6) global address (e.g., 192.168.1.1) used by the Network Layer for global end-to-end packet delivery.
  • 3. Port Address: 16-bit integer (e.g., Port 80 for HTTP, Port 53 for DNS) used by the Transport Layer to identify the specific application process running on a host.
  • 4. Specific (Application) Address: User-friendly identifiers like URLs (www.google.com) or email addresses (user@domain.com) used at the Application Layer.

4.2 Unguided Media: Wireless Communication

  • Radio Waves (3 kHz to 1 GHz): Omnidirectional (propagate in all directions). Can penetrate solid walls, making them ideal for indoor and outdoor mobile communication (AM/FM radio, cordless phones, cellular networks). Highly susceptible to interference.
  • Microwaves (1 GHz to 300 GHz): Unidirectional (focused narrow beams). Require clear Line-of-Sight (LOS) between transmitting and receiving antennas. Cannot penetrate walls. Used in:
    • Terrestrial Microwave: Parabolic dish and horn antennas mounted on high towers (repeater spacing 30-50 km due to earth curvature).
    • Satellite Microwave: Geostationary satellites (altitude 35,786 km) act as microwave repeaters in the sky.
  • Infrared Waves (300 GHz to 400 THz): Very high frequency, cannot penetrate opaque walls. Used for short-range line-of-sight communication (TV remote controls, IrDA wireless mouse), preventing interference between adjacent rooms.

5. Switching: Packet Switching and its Types (Ch. 8.3)

In large networks, a direct point-to-point connection between every pair of nodes is impossible. A switched network connects multiple devices through intermediate switching nodes. While circuit switching reserves a dedicated physical path (used in legacy telephone calls), modern data networks use Packet Switching.

Fig 1.4: Packet Switching: Datagram Networks vs Virtual-Circuit Networks

5.1 Datagram Networks (Connectionless)

  • Working Principle: The message is divided into independent packets called datagrams. Each datagram contains the complete destination IP address in its header.
  • Routing: Each router evaluates the destination address of every packet independently and looks up its routing table to choose the next hop. Packets belonging to the same message may take different routes depending on network congestion and link failures.
  • Characteristics: No connection setup phase; packets may arrive out of order or be delayed; routers do not maintain per-connection state tables (highly fault-tolerant). This is the underlying architecture of the Internet Protocol (IP).

5.2 Virtual-Circuit Networks (Connection-Oriented)

  • Working Principle: A single logical connection path called a Virtual Circuit (VC) is established between source and destination before data packets are transmitted.
  • Three Phases:
    1. Setup Phase: A setup frame travels from source to destination, establishing entries in the switching tables and assigning local Virtual Circuit Identifiers (VCI) at each switch.
    2. Data Transfer Phase: Packets carry only the short VCI (not full 32-bit or 128-bit addresses). All packets follow the exact same pre-determined physical route in sequential order.
    3. Teardown Phase: When communication ends, a teardown signal releases the table entries and bandwidth along the path.
  • Characteristics: Guaranteed in-order packet arrival; predictable delay; but vulnerable to link failures (if a switch on the path crashes, the entire connection drops and must be re-established). Used in ATM, Frame Relay, and MPLS.

1. Error Detection and Correction (Ch. 10.1 - 10.4)

Networks transmit electromagnetic signals across physical media. Noise, electromagnetic radiation, and physical line defects can alter signal voltage levels, causing transmitted 0s to invert to 1s and vice versa.

1.1 Types of Errors

  • Single-Bit Error: Only one bit in a given data unit (byte or packet) is corrupted. Relatively rare in serial communications because noise pulses typically last longer than the duration of a single bit.
  • Burst Error: Two or more bits in the data unit are corrupted. The length of the burst is measured from the first corrupted bit to the last corrupted bit (even if intermediate bits in between are intact). Burst errors are common in high-speed networks where a brief noise spike lasts across hundreds of bits.

1.2 Redundancy, Detection vs Correction

To detect or correct errors, we must append extra bits to the original data — known as Redundant Bits. The receiver uses these redundant bits to verify the integrity of the data.

  • Error Detection: The receiver can only determine if an error occurred. The receiver discards the corrupted frame and asks the sender to retransmit (ARQ — Automatic Repeat Request). Used when error rates are low (fiber, wired LANs).
  • Forward Error Correction (FEC): The receiver determines not only that an error occurred, but precisely which bit positions flipped, allowing immediate correction without retransmission. Used in satellite links, wireless networks with high round-trip delays, and real-time streaming where retransmission is too slow.

1.3 Block Coding & Hamming Distance

In block coding, we divide the message into $k$-bit datawords. We add $r$ redundant bits to each block to produce an $n$-bit codeword, where $n = k + r$. The code is designated as $(n, k)$.

  • Hamming Distance $d(x, y)$: The number of bit positions in which two codewords of equal length differ. Computed by taking the bitwise XOR of the two codewords and counting the number of 1s (Hamming weight).
    Example: $x = 10101, y = 11100$. $x \oplus y = 01001 \rightarrow$ Hamming distance = 2.
  • Minimum Hamming Distance ($d_{min}$): The smallest Hamming distance between all possible valid codeword pairs in a code set.
Crucial Theorem for Error Detection & Correction:
• To detect up to 's' errors: d_min ≥ s + 1
• To correct up to 't' errors: d_min ≥ 2t + 1

Why? If $d_{min} = 3$: Any single bit flip produces an invalid codeword ($s=2$ errors detected because distance from any valid codeword is at least 1). If 1 bit flips ($t=1$), the invalid word is closer to the original valid word (distance 1) than any other valid word (distance $\ge 2$), allowing unambiguous correction.

1.4 Cyclic Codes and Cyclic Redundancy Check (CRC)

Cyclic codes are a category of linear block codes where cyclically shifting any valid codeword produces another valid codeword. The most powerful and ubiquitous cyclic code used in networks (Ethernet, Wi-Fi, HDLC) is the Cyclic Redundancy Check (CRC).

  • Generator Polynomial $G(x)$: The divisor used in modulo-2 arithmetic. A polynomial such as $x^3 + x + 1$ translates into the binary bit pattern 1011 (highest power $x^3 \rightarrow 1$, $x^2 \rightarrow 0$, $x^1 \rightarrow 1$, $x^0 \rightarrow 1$).
  • Encoding Algorithm (Sender):
    1. Let the dataword have $k$ bits and the divisor have $n+1$ bits (degree $n$).
    2. Append $n$ zeros to the right of the dataword.
    3. Divide the augmented dataword by the divisor using Modulo-2 Binary Division (bitwise XOR, no carries, no borrows).
    4. The resulting $n$-bit remainder is the CRC Checksum.
    5. Replace the appended $n$ zeros with this remainder to form the transmitted codeword.
  • Decoding Algorithm (Receiver):
    1. Divide the received codeword by the identical divisor using modulo-2 division.
    2. If the remainder is all zeros (000), the frame is accepted (no error detected).
    3. If the remainder is non-zero, an error occurred; the frame is discarded.

1.5 Internet Checksum

The traditional Checksum is used primarily by network and transport layer protocols (IPv4, TCP, UDP).

  • Sender Algorithm:
    1. Divide the message into 16-bit words.
    2. Add all 16-bit words together using One's Complement Addition (if a carry out occurs from the 16th bit, wrap it around and add it to the sum).
    3. Take the one's complement (invert all bits: $0 \rightarrow 1, 1 \rightarrow 0$) of the final sum. This is the checksum.
    4. Append the checksum to the payload.
  • Receiver Algorithm:
    1. Sum all received 16-bit words including the checksum using one's complement arithmetic.
    2. Take the complement of the total. If the result is all 0s (0x0000), accept the packet. Otherwise, reject.

2. Data Link Control (DLC) Services (Ch. 11.1 - 11.4)

Data Link Control handles the design of node-to-node communication across a single physical link.

2.1 Framing & Bit Stuffing

Since physical media deliver continuous streams of raw bits, the Data Link Layer must demarcate the start and end of each transmission unit. This is called Framing.

  • Character-Oriented (Byte-Oriented) Framing: Uses a special 8-bit character flag (e.g., SYN or FLAG) at the start and end. If the user data itself contains the flag character, a Byte Stuffing mechanism inserts an escape character (DLE — Data Link Escape) immediately before it.
  • Bit-Oriented Framing & Bit Stuffing: Uses a unique delimiter flag pattern 01111110 (six consecutive 1s surrounded by 0s) at the beginning and end of the frame.
    Bit Stuffing Rule: Whenever the transmitter detects five consecutive 1s in the data stream, it automatically stuffs a 0 immediately after the fifth 1, regardless of what the next bit is. The receiver detects any pattern of five 1s followed by a 0 and automatically strips the 0, restoring the exact original payload.

2.2 Flow Control & Error Control

  • Flow Control: Prevents a fast sender from overwhelming a slow receiver's input buffer. Uses feedback: the receiver sends permission (acknowledgments or window size updates) allowing the sender to transmit more data.
  • Error Control: Detects corrupted, lost, or duplicated frames and triggers retransmissions. Implemented using ARQ (Automatic Repeat Request), sequence numbers, positive acknowledgments (ACK), and retransmission timers.

🔑 Why is Send Window Size in GBN at most $2^m - 1$?
If $m=2$ (sequence numbers 0, 1, 2, 3), suppose we allowed $S_w = 2^2 = 4$. The sender transmits frames 0, 1, 2, 3. The receiver accepts all and sends cumulative ACK 0 (requesting frame 0 of the next round). If this ACK is lost, the sender times out and retransmits frames 0, 1, 2, 3. The receiver, expecting new frames 0, 1, 2, 3, would mistakenly accept the retransmitted frames as brand new data! By capping $S_w \le 2^m - 1$, the old and new windows never overlap, eliminating ambiguity.

3. High-Level Data Link Control (HDLC) (Ch. 11.3)

HDLC is a bit-oriented synchronous data link protocol developed by ISO. It supports both half-duplex and full-duplex communication over point-to-point and multipoint links.

  • Transfer Modes:
    • Normal Response Mode (NRM): Unbalanced configuration with one primary station and one or more secondary stations. Secondary can transmit only in response to a poll from the primary.
    • Asynchronous Balanced Mode (ABM): Balanced point-to-point configuration where either station can initiate transmission without authorization (used in modern links).
  • HDLC Frame Format:
    Flag (8b) Address (8b+) Control (8 or 16b) Information Field (Variable) FCS (16 or 32b) Flag (8b)
    01111110 Secondary address Defines Frame Type User Data (in I-frames) CRC-CCITT 01111110
  • Three Types of HDLC Frames (Determined by Control Field):
    • Information Frames (I-Frames): Carry user data from higher layers plus flow/error control information piggybacked (Send sequence number $N(S)$ and Receive sequence number $N(R)$). First bit is 0.
    • Supervisory Frames (S-Frames): Do not carry user data. Carry flow and error control commands (ACK, NAK, Receive Ready — RR, Receive Not Ready — RNR, Reject — REJ, Selective Reject — SREJ). First two bits are 10.
    • Unnumbered Frames (U-Frames): Used for link management, session initialization, and disconnect commands (SABM, DISC, UA). First two bits are 11.

4. Media Access Control (MAC) (Ch. 12.1 - 12.2)

When multiple stations share a single broadcast transmission medium, their signals will collide if they transmit concurrently. Media Access Control (MAC) protocols coordinate which device is allowed to transmit.

Fig 2.4: Random Access Protocols Comparison: ALOHA and CSMA Variants

4.1 Random Access Protocols

1. ALOHA Protocols

  • Pure ALOHA: Whenever a station has data, it transmits immediately. If two stations transmit overlapping frames, a collision occurs and frames are destroyed. Stations wait a random backoff time before retransmitting.
    Vulnerable Time = $2 \times T_{fr}$. Maximum theoretical throughput: $S_{max} = \frac{1}{2e} \approx 0.184$ (18.4%).
  • Slotted ALOHA: Time is divided into discrete slots equal to $T_{fr}$. A station can transmit only at the beginning of a time slot. Synchronized clocks are required.
    Vulnerable Time = $1 \times T_{fr}$. Maximum throughput: $S_{max} = \frac{1}{e} \approx 0.368$ (36.8% — double that of Pure ALOHA!).

2. CSMA (Carrier Sense Multiple Access)

Principle: "Sense before transmit" (or "Listen before speaking"). A station monitors the channel to verify if it is idle or busy.

  • 1-Persistent CSMA: If channel is idle, transmit immediately with probability 1. If busy, keep continuously sensing until it becomes idle, then transmit. High collision probability if two stations were waiting for the same channel to free up.
  • Non-Persistent CSMA: If idle, transmit immediately. If busy, wait a random amount of time and sense again. Reduces collisions significantly, but introduces idle channel wastage.
  • p-Persistent CSMA: Used in slotted channels. If idle, transmit with probability $p$; with probability $(1-p)$, wait for the next slot. Minimizes collisions while maximizing channel utilization.

3. CSMA/CD (Collision Detection — IEEE 802.3 Wired Ethernet)

Principle: "Listen while talking". Stations monitor the cable voltage while transmitting. If the observed voltage doubles (signaling collision), transmission is halted immediately, a 32-bit Jamming Signal is broadcast to alert all nodes, and the station executes the Binary Exponential Backoff algorithm ($0 \le k \le 2^c - 1$, wait $k \times 512$ bit times).

Minimum Frame Size Condition in CSMA/CD:
To ensure a transmitting station detects collisions before finishing transmission:
T_frame ≥ 2 × T_propagation  &implies;  L_min ≥ 2 × Propagation_Delay × Bandwidth
For standard 10 Mbps Ethernet: Minimum frame size = 64 bytes (512 bits).

4. CSMA/CA (Collision Avoidance — IEEE 802.11 Wireless LAN)

In wireless networks, collision detection is impossible because a station's own high-power transmission drowns out any weak incoming collision signal from another station. Hence, collisions must be avoided before they occur:

  • Interframe Space (IFS): Station waits until the channel is idle for a duration equal to IFS (e.g., DIFS).
  • Contention Window: Expands exponentially if collisions occur; counts down when the channel is idle.
  • RTS/CTS Handshake: Solves the Hidden Terminal Problem. Sender broadcasts a short Request to Send (RTS) frame. Receiver responds with a Clear to Send (CTS) frame. All neighboring nodes overhearing CTS silence their transmitters for the reserved duration (NAV — Network Allocation Vector).
  • Mandatory Acknowledgments (ACK): Every transmitted data frame must be explicitly acknowledged by the receiver.

4.2 Controlled Access Protocols

  • Reservation: Stations divide time into intervals with a reservation frame preceding data frames. Each station reserves a slot in advance by setting a bit.
  • Polling: One primary station and multiple secondary stations. The primary uses Poll to ask secondaries if they have data to send, and Select when sending data to a secondary.
  • Token Passing: Stations are organized in a logical ring. A special small frame called the Token circulates from station to station. Only the node currently possessing the token is permitted to transmit data. After transmitting or when its Token Holding Timer expires, it forwards the token to its downstream neighbor. Eliminates collisions completely.

5. Point-to-Point Protocol (PPP) (Ch. 11.4)

The Point-to-Point Protocol (PPP) is the dominant data link protocol used for establishing direct connections between two nodes (e.g., home PC to Internet Service Provider over DSL, cable modem, or leased lines).

  • Services Provided by PPP: Framing, bit/byte stuffing, link quality testing, authentication (PAP/CHAP), network layer protocol negotiation and multiplexing (IPv4, IPv6, AppleTalk).
  • Services NOT Provided: No flow control (relies on higher layers), no error correction (simple CRC error detection only; damaged frames are silently dropped), no addressing (simple point-to-point link).
  • PPP Architecture:
    • LCP (Link Control Protocol): Responsible for establishing, configuring, testing, and terminating the data link.
    • Authentication Protocols: PAP (Password Authentication Protocol — plain text 2-way handshake) and CHAP (Challenge Handshake Authentication Protocol — secure 3-way handshake with MD5 hashing).
    • NCP (Network Control Protocols): Multiple protocols (like IPCP) that configure network-layer settings (e.g., dynamically assigning IP addresses to the client).
  • PPP Transition Phases: Dead → Establish (LCP) → Authenticate (PAP/CHAP) → Network (NCP) → Open (Data Transfer) → Terminate → Dead.

💡 ELI5: What is the Network Layer? (The GPS and Postal Van System)
If the Data Link Layer is your postman delivering an envelope to the very next house on your street, the Network Layer is the global logistics network! It puts an IP address on your envelope (e.g., "123 Country Road, Paris, France"). Even if the postman has never been to France, routers act like airport cargo hubs: 1. 1. Network Layer Services & Packet Switching (Ch. 18.1 & 18.2)

The Network Layer is responsible for host-to-host communication across heterogeneous networks.

  • Packetizing: Encapsulates data from the transport layer into network datagrams at the source and decapsulates them at the destination without examining payload contents.
  • Routing: The process of discovering optimal paths from source to destination across multiple interconnected routers using distributed routing algorithms.
  • Forwarding: The action taken by a router when a packet arrives on an input link — looking up the destination IP in the local forwarding table and transferring the packet to the appropriate output interface buffer.
  • Error & Flow Control: Provided minimally at Layer 3 (mostly delegated to transport layer TCP); uses ICMP (Internet Control Message Protocol) to report delivery problems.

2. IPv4 Addressing: Classful, CIDR, Subnetting & NAT (Ch. 18.4)

An IPv4 address is a 32-bit binary number that uniquely and universally identifies the connection of a host or router interface to the Internet. Address space = $2^{32} = 4,294,967,296$ addresses ($\approx 4.3$ billion).

2.2 Classless Addressing (CIDR — Classless Inter-Domain Routing)

Classful addressing wasted billions of addresses (e.g., an organization needing 1,000 addresses had to take a Class B with 65,534 addresses, wasting 98%!). In 1993, CIDR abolished rigid classes:

  • Slash Notation (/n): Addresses are written as a.b.c.d/n, where $n$ is the prefix length (number of bits assigned to the network prefix).
  • Host Bits: $32 - n$. Total addresses in block = $2^{32 - n}$. Usable host addresses = $2^{32 - n} - 2$.
  • Network Address (First Address): Bitwise AND between IP address and the Subnet Mask. Represents the entire network block.
  • Direct Broadcast Address (Last Address): Host bits are all set to 1. Used to broadcast to all hosts in that subnet.

2.3 Network Address Translation (NAT / NAPT)

To prevent global IPv4 address exhaustion, RFC 1918 reserved specific blocks for private internal networks:

  • 10.0.0.0/8 (10.0.0.0 – 10.255.255.255) — Single large private enterprise block.
  • 172.16.0.0/12 (172.16.0.0 – 172.31.255.255) — 16 contiguous private blocks.
  • 192.168.0.0/16 (192.168.0.0 – 192.255.255.255) — 256 contiguous home/office blocks.

These private addresses cannot be routed across the public Internet. A NAT router sits at the network border and translates internal private IP addresses into a single registered public IP address using Port Address Translation (NAPT / PAT):

  • NAT Translation Table: Maps tuples (Private IP, Private Port) ↔ (Public IP, Assigned External Port).
  • Outbound: Router replaces internal source IP (e.g., 192.168.1.15:4500) with public IP (e.g., 203.0.113.5:8001) and records mapping.
  • Inbound: When replies return to port 8001, NAT router looks up table and forwards packet to 192.168.1.15:4500.
  • Pros: Conserves public IPv4 addresses; provides security (internal network invisible to outside scanners).
    Cons: Violates end-to-end network principle; breaks peer-to-peer protocols (VoIP, BitTorrent) without STUN/TURN relays.

3. IPv4 and IPv6 Datagram Formats (Ch. 18.4 & 22.2)

3.1 IPv4 Datagram Header

Fig 3.1: IPv4 Datagram Header Field Layout (Standard 20-byte base)
  • VER (4 bits): Version number; always 4 (binary 0100).
  • HLEN (4 bits): Header Length in 4-byte (32-bit) words. Min value is 5 ($5 \times 4 = 20$ bytes without options); max value is 15 ($15 \times 4 = 60$ bytes).
  • Service Type / DSCP (8 bits): Quality of Service (QoS) classification (precedence, delay, throughput, reliability).
  • Total Length (16 bits): Entire length of datagram (Header + Data) in bytes. Maximum possible IPv4 datagram size = $2^{16} - 1 = 65,535$ bytes.
  • Identification (16 bits): Unique ID assigned by sender to identify all fragments belonging to the same original datagram.
  • Flags (3 bits):
    • Bit 0: Reserved (must be 0).
    • Bit 1: DF (Don't Fragment): If 1, routers are forbidden from fragmenting. If MTU is too small, packet is dropped and ICMP "Fragmentation Needed" is sent.
    • Bit 2: MF (More Fragments): If 1, more fragments follow. If 0, this is the last fragment.
  • Fragment Offset (13 bits): Relative position of this fragment's data within the original unfragmented payload, measured in units of 8 bytes.
  • Time to Live — TTL (8 bits): Hop counter to prevent packets from looping endlessly. Every router decrements TTL by 1. When TTL reaches 0, the packet is discarded and an ICMP "Time Exceeded" is returned to the sender (used by traceroute).
  • Protocol (8 bits): Identifies the higher transport-layer protocol: 1 = ICMP, 6 = TCP, 17 = UDP, 89 = OSPF.
  • Header Checksum (16 bits): Protects against header corruption during transit. Recomputed at every router because TTL changes!
  • Source IP (32 bits) & Destination IP (32 bits): IPv4 addresses of sender and final receiver.

3.2 IPv6 Datagram Header & Enhancements

IPv6 addresses the total exhaustion of 32-bit IPv4 by offering 128-bit addresses ($2^{128} \approx 3.4 \times 10^{38}$ addresses — enough to assign millions of IPs to every atom on Earth!).

Fig 3.2: IPv6 Base Header Layout (Streamlined 8 fields)

Key Advantages of IPv6 over IPv4:

  • Fixed 40-byte Base Header: Eliminates HLEN and options parsing. Routers process headers in hardware at wire speed.
  • No Header Checksum: Checksums are handled at Data Link (CRC) and Transport (TCP/UDP). Removing it eliminates recomputing checksums at every hop!
  • No Router-level Fragmentation: Routers never fragment packets. End-hosts use Path MTU Discovery. If packet is too large, router sends ICMPv6 "Packet Too Big".
  • Extension Headers: Inserted between base header and payload via a daisy-chain Next Header pointer (Hop-by-hop options, Routing, Fragment, ESP, AH).
  • Built-in Security: Mandatory support for IPsec (Encryption and Authentication).

4. Routing Algorithms: DVR, LSR, and PVR (Ch. 20.1 - 20.3)

Routing protocols allow routers to continuously share knowledge of network topology and calculate the least-cost path to every destination.

4.1 Distance Vector Routing (DVR & Bellman-Ford)

  • Philosophy: "Tell your neighbors about the entire world."
  • Each router maintains a vector (table) of distances: Cost to every destination, Next-hop router.
  • Bellman-Ford Equation: $D_x(y) = \min_v \{ c(x, v) + D_v(y) \}$, where $v$ ranges over all neighbors of $x$.
  • Count-to-Infinity Problem: Good news (link cost decrease) propagates rapidly, but bad news (link failure or cost increase) propagates extremely slowly through loops because routers advertise paths to each other that depend on each other.
    Solutions:
    • Split Horizon: Do not advertise a route back to the neighbor from whom it was learned.
    • Poison Reverse: Advertise that route back to that neighbor with cost = $\infty$ (infinity).

4.2 Link State Routing (LSR & Dijkstra's Algorithm)

  • Philosophy: "Tell the entire world about your immediate neighbors."
  • Five Steps of Link State Routing:
    1. Neighbor Discovery: Router sends HELLO packets on all links to discover direct neighbors.
    2. Link Cost Measurement: Router measures delay or bandwidth cost to each neighbor (e.g., using echo packets).
    3. LSP Construction: Router builds a Link State Packet (LSP) containing its ID, sequence number, age, and list of direct neighbors with link costs.
    4. Reliable Flooding: Floods the LSP to every other router in the network. Every router builds an identical Link State Database (LSDB) — a complete network topology map.
    5. Dijkstra's SPF Computation: Each router independently runs Dijkstra's Shortest Path First algorithm on the LSDB, producing a shortest path tree with itself as the root.

4.3 Path Vector Routing (PVR)

Used for inter-domain routing where distance vector and link state fail due to scalability and policy conflicts. Instead of advertising costs, routers advertise the entire sequence of Autonomous Systems (AS Path) traversed to reach the destination:

  • Loop Prevention: If a router sees its own AS number in the advertised AS Path, it immediately drops the advertisement, preventing loops completely.
  • Policy Enforcement: Allows network providers to refuse traffic from competitors or prefer paths based on economic agreements rather than pure shortest hop count.

5.1 Open Shortest Path First (OSPF) Details

  • Hierarchical Area Structure: Large Autonomous Systems are subdivided into Areas. Area 0 is the Backbone Area. All other areas must connect to Area 0 through Area Border Routers (ABR). Routers connecting to external ASs are Autonomous System Boundary Routers (ASBR).
  • OSPF Packet Types:
    1. Hello (Type 1): Establishes and maintains neighbor relationships; elects Designated Router (DR) and Backup DR (BDR).
    2. Database Description - DBD (Type 2): Summarizes LSDB contents during adjacency initialization.
    3. Link State Request - LSR (Type 3): Requests full details of specific outdated LSPs.
    4. Link State Update - LSU (Type 4): Transmits newly advertised LSPs (reliable flooding).

6. Multicasting Routing: MOSPF (Ch. 21.3.2)

  • Unicast vs Broadcast vs Multicast: Unicast = 1-to-1; Broadcast = 1-to-All; Multicast = 1-to-Group (delivers one stream to multiple designated receivers without replicating packets across shared links).
  • Multicast Trees:
    • Source-Based Tree: A separate shortest path distribution tree is calculated for each source sending to the group.
    • Group-Shared Tree: A single shared rendezvous point / core router acts as the root of the tree for all sources.
  • MOSPF (Multicast OSPF): An extension of OSPF for multicasting. Routers broadcast a new Group-Membership LSA detailing which multicast groups have active listeners on their subnets. When a multicast packet arrives from source $S$ to group $G$, the router computes an on-demand Dijkstra shortest-path source-based tree rooted at $S$ to forward packets only down branches leading to active group members.

An IP address gets a letter to your apartment building front door. But there are 100 people living in different apartments! The Transport Layer adds the Port Number — the apartment door number! Now consider how you communicate: • UDP (User Datagram Protocol) is like a Postcard: You scribble a message and drop it in the box. 1. Introduction to Transport-Layer Services (Ch. 23.1 & 23.2)

The Transport Layer sits in the heart of the protocol stack. It bridges the gap between the application processes above and the lower physical/network communication facility below.

1.1 Process-to-Process Communication & Port Numbers

While the network layer delivers packets between hosts, the transport layer delivers data between specific processes (running programs) on those hosts. A process is addressed by a Port Number (16-bit integer, range 0 to 65,535):

  • Well-Known Ports (0 to 1023): Assigned by IANA to standard universal server services (HTTP 80, HTTPS 443, DNS 53, FTP 20/21, SSH 22, SMTP 25).
  • Registered Ports (1024 to 49,151): Registered for specific commercial applications (e.g., MySQL 3306, PostgreSQL 5432).
  • Dynamic / Ephemeral / Private Ports (49,152 to 65,535): Temporary ports assigned automatically by the operating system to client programs when opening a connection.
  • Socket Address: The combination of an IP Address + Port Number (e.g., 192.168.1.50:8080). Defines an unambiguous endpoint in a network communication.

1.2 Multiplexing and Demultiplexing

  • Multiplexing (Sender): The transport layer collects data segments from multiple active application processes, adds transport headers with source and destination port numbers, and passes them down to the single network layer.
  • Demultiplexing (Receiver): The transport layer receives datagrams from the network layer, inspects the destination port number in the header, and delivers each payload to the exact socket of the corresponding application process.

2. User Datagram Protocol — UDP (Ch. 24.1)

UDP is a connectionless, unreliable, lightweight transport protocol. It adds almost no overhead beyond port addressing and error detection.

2.1 UDP Services and Characteristics

  • Connectionless: No handshake or setup prior to data transmission. Every datagram is completely independent.
  • Unreliable: No acknowledgments, no retransmissions, no sequencing, and no flow or congestion control. If a packet is corrupted, it is discarded without warning.
  • Preserves Message Boundaries: Unlike TCP's byte stream, UDP delivers data in discrete datagrams — if an application writes 500 bytes to a UDP socket, the receiver reads exactly 500 bytes in a single read call.
  • Minimal Header Overhead: Fixed at only 8 bytes (compared to TCP's minimum 20 bytes).

2.3 When is UDP Preferred over TCP?

  • Real-time multimedia streaming (VoIP, Zoom, live video) where delay jitter is unacceptable and late retransmitted packets are useless.
  • Simple request-reply interactions (DNS queries, DHCP) where connection setup overhead would double transaction latency.
  • Multicasting and broadcasting (TCP is strictly point-to-point unicast).

3. Transmission Control Protocol — TCP (Ch. 24.2 - 24.3)

TCP is a connection-oriented, reliable, stream-delivery transport protocol. It guarantees in-order, error-free delivery of bytes across an unreliable underlying IP network.

3.1 TCP Services & Key Features

  • Stream Delivery Service: TCP views data as an unstructured, continuous sequence of bytes (a byte stream), rather than distinct messages.
  • Full-Duplex Communication: Data can travel simultaneously in both directions between client and server over the same connection.
  • Byte-Level Numbering: Every single byte in the stream is assigned a unique 32-bit sequence number. If a segment carries bytes 5001 to 6000, its Sequence Number in the header is 5001.
  • Cumulative Acknowledgments: The ACK number indicates the next byte expected by the receiver. An ACK of 6001 confirms receipt of all bytes up to 6000.

3.2 TCP Segment Header Format

Fig 4.1: TCP Segment Header Layout (Detailed 32-bit field structure)
  • Source Port (16b) & Destination Port (16b): Identifies sending and receiving processes.
  • Sequence Number (32b): Byte offset of the first data byte in this segment.
  • Acknowledgment Number (32b): Next byte expected from the other party (valid only when ACK flag = 1).
  • HLEN / Data Offset (4b): Length of TCP header in 32-bit words ($5 \times 4 = 20$ bytes min, 60 bytes max).
  • Control Flags (6 bits):
    • URG: Urgent Pointer is valid; data should be processed with priority.
    • ACK: Acknowledgment field is valid (set on almost every segment after handshake).
    • PSH (Push): Sender requests immediate transmission to application without waiting to fill buffer.
    • RST (Reset): Abruptly aborts and resets an invalid or rejected connection.
    • SYN (Synchronize): Synchronizes initial sequence numbers during connection establishment.
    • FIN (Finish): Sender has no more data to send; initiates graceful termination.
  • Window Size — $rwnd$ (16 bits): Receiver's advertised buffer size in bytes for Flow Control.
  • Checksum (16 bits): Mandatory 16-bit one's complement sum over a 12-byte pseudo-header, TCP header, and data.
  • Urgent Pointer (16 bits): Offset to the end of urgent data if URG flag is set.

3.3 TCP Connection Life Cycle

Fig 4.2: TCP Connection Life Cycle: 3-Way Handshake and 4-Way Connection Teardown

1. Connection Establishment: The Three-Way Handshake

  1. Step 1 (SYN from Client): Client picks random Initial Sequence Number ($ISN_c = x$) and sends SYN=1, seq=x. Consumes 1 sequence number. No application data allowed.
  2. Step 2 (SYN + ACK from Server): Server allocates buffers, picks its own $ISN_s = y$, and replies with SYN=1, ACK=1, seq=y, ack=x+1.
  3. Step 3 (ACK from Client): Client confirms with ACK=1, seq=x+1, ack=y+1. May carry initial user data. Connection is now ESTABLISHED!
🔑 Why a 3-Way Handshake? (And what is SYN Flooding?)
A 2-way handshake is insufficient because delayed or duplicated SYN packets from old dead connections could arrive at the server, causing it to allocate resources for phantom sessions. The 3rd step proves to the server that the client is live and genuinely requested this connection.
SYN Flood Attack: An attacker floods a server with thousands of fake SYNs with spoofed IPs, ignoring the SYN+ACK replies. The server leaves half-open connection tables until memory exhausts. Defense: SYN Cookies (server encodes connection parameters cryptographically into the server's sequence number $y$, allocating zero state memory until the client's valid 3rd ACK returns).

2. Connection Termination: The Four-Way Handshake

TCP is full-duplex, so each direction must be terminated independently:

  1. Client → Server (FIN): Client sends FIN=1, seq=u. Client enters FIN_WAIT_1.
  2. Server → Client (ACK): Server sends ACK=1, ack=u+1. Server enters CLOSE_WAIT; client enters FIN_WAIT_2. The connection is now Half-Closed: client can no longer send, but server can still transmit remaining data!
  3. Server → Client (FIN): When finished, server sends FIN=1, seq=w, ack=u+1. Server enters LAST_ACK.
  4. Client → Server (ACK): Client acknowledges with ACK=1, ack=w+1 and enters TIME_WAIT state for $2 \times \text{MSL}$ (Maximum Segment Lifetime, typically $2 \times 60s = 120s$).
    Why TIME_WAIT? To ensure the final ACK reached the server (if lost, server retransmits FIN, which client can re-ACK), and to allow old delayed duplicate packets to die out in the network before a new connection reuses the same port!

4. TCP Flow Control & Silly Window Syndrome (Ch. 24.3.4)

Flow control matches the sender's transmission rate to the receiver's reading speed using a dynamic Sliding Window:

  • Receiver Advertised Window ($rwnd$): $rwnd = \text{Buffer Size} - (\text{Bytes Received} - \text{Bytes Read by App})$. The receiver reports $rwnd$ in every ACK.
  • Zero Window Notification: If the receiver buffer fills up, it advertises $rwnd = 0$, telling the sender to pause. Sender starts a Persistence Timer and periodically sends 1-byte Window Probe segments to check if buffer space has opened up.
  • Silly Window Syndrome (SWS): Occurs when data is transmitted in tiny fragments (e.g., 1 byte of data wrapped in a 40-byte TCP/IP header — 97% overhead!):
    • Receiver-Side SWS: Occurs when a slow application reads data 1 byte at a time, causing the receiver to advertise a tiny 1-byte window. Solution (Clark's Algorithm): Force receiver to advertise $rwnd = 0$ until either half the buffer is empty or space for a full Maximum Segment Size (MSS) is available.
    • Sender-Side SWS: Occurs when an application generates tiny data chunks. Solution (Nagle's Algorithm): Send the first byte immediately. Buffer all subsequent tiny bytes until either: (1) a full MSS is accumulated, or (2) the ACK for the previous outstanding segment arrives.

5. TCP Error Control (Ch. 24.3.6)

  • Retransmission Timeout (RTO): Dynamically computed from smoothed Round Trip Time ($RTT_s$) using Jacobson's algorithm: $RTO = RTT_s + 4 \times RTT_d$.
  • Karn's Algorithm: Never calculate RTT samples for retransmitted segments (since you cannot tell if an ACK corresponds to the first or second transmission). On timeout, double the timeout value (Exponential Backoff).
  • Fast Retransmit: When a single segment is lost but subsequent segments arrive, the receiver sends duplicate ACKs. When the sender receives 3 Duplicate ACKs for the same sequence number, it immediately retransmits the missing segment without waiting for the RTO timer to expire!

6. TCP Congestion Control (Ch. 24.3.7 - 24.3.9)

While flow control protects the receiver, Congestion Control protects the intermediate routers and network links from being overwhelmed by global traffic.

Effective Transmission Window:
Actual Window = min(rwnd, cwnd)
Where:
• rwnd: Receiver Advertised Window (Flow Control limit)
• cwnd: Congestion Window maintained by sender (Congestion Control limit)
Fig 4.3: TCP Congestion Control: Slow Start, Additive Increase, Tahoe vs Reno Recovery

6.1 The Four Core Congestion Control Phases

  1. Phase 1 — Slow Start (Exponential Growth):
    • Initial state: $cwnd = 1 \text{ MSS}$ (or 2 to 4 MSS).
    • For every ACK received, $cwnd$ increases by 1 MSS: $cwnd \gets cwnd + 1 \text{ MSS}$.
    • Over one Round Trip Time (RTT), $cwnd$ doubles ($1 \rightarrow 2 \rightarrow 4 \rightarrow 8 \rightarrow 16 \dots$).
    • Slow start continues until $cwnd \ge ssthresh$ (Slow Start Threshold).
  2. Phase 2 — Congestion Avoidance (Additive Increase):
    • Once $cwnd \ge ssthresh$, exponential growth becomes dangerous. Growth shifts to a linear increase.
    • $cwnd$ increases by 1 MSS per full RTT (or $cwnd \gets cwnd + \frac{1}{cwnd}$ per ACK).
    • This is the Additive Increase phase of AIMD (Additive Increase Multiplicative Decrease).
  3. Phase 3 — Fast Retransmit:
    • Upon receiving 3 Duplicate ACKs, sender concludes a packet was lost due to mild congestion, and immediately retransmits the missing segment.
  4. Phase 4 — Fast Recovery: TCP Tahoe vs TCP Reno:
    • TCP Tahoe (Legacy): On either timeout or 3 Duplicate ACKs, sets $ssthresh = cwnd / 2$ and resets $cwnd = 1 \text{ MSS}$! Goes back to slow start. Harsh and overly penalizing.
    • TCP Reno (Modern Standard):
      • On Timeout (Severe Congestion): Sets $ssthresh = cwnd / 2$, resets $cwnd = 1$, enters Slow Start.
      • On 3 Duplicate ACKs (Mild Congestion): Enters Fast Recovery. Sets $ssthresh = cwnd / 2$, sets $cwnd = ssthresh + 3 \text{ MSS}$ (accounting for 3 buffered segments), and skips slow start directly into Congestion Avoidance (linear growth)! Preserves high throughput.

MODULE 5 — Application Layer: HTTP, FTP, Email, DNS, TELNET & SSH

💡 ELI5: What is the Application Layer? (The Restaurant Analogy)
All the lower layers (Physical, Data Link, Network, Transport) are like the kitchen staff, trucks, roads, and delivery boxes. 1. Introduction to the Application Layer & Client-Server Programming (Ch. 25.1 & 25.2)

The Application Layer is the top layer in both the OSI and TCP/IP protocol suites. It provides network services directly to end-user software programs.

1.1 Application Architectures

  • Client-Server Architecture: A centralized, dedicated host called the Server is always turned on and listens on a well-known port. Multiple Clients initiate contact with the server to request resources. Clients do not communicate directly with each other (e.g., Web servers, Email servers, Database servers).
  • Peer-to-Peer (P2P) Architecture: There is no central dedicated server. Arbitrary pairs of connected end-hosts called peers communicate directly with each other and share resources (storage, bandwidth). Highly scalable, but harder to manage and secure (e.g., BitTorrent).
  • Hybrid Architecture: Combines both paradigms — a central server handles authentication and directory indexing, while file transfers take place directly peer-to-peer (e.g., Skype, early Napster).

1.2 Client-Server Programming via Sockets

A Socket is the software abstraction and Application Programming Interface (API) between an application process and the underlying transport layer.

  • TCP Socket Life Cycle:
    1. Server: Calls socket() → bind() to port → listen() for incoming requests → accept() (blocks waiting for a client).
    2. Client: Calls socket() → connect() to server IP and port (triggers TCP 3-way handshake).
    3. Data Exchange: Both sides call send() / write() and recv() / read() over the established full-duplex stream.
    4. Termination: Calling close() tears down the connection (4-way handshake).
  • Concurrent vs Iterative Servers:
    • Iterative Server: Handles one client request to completion before accepting the next client. Inefficient if requests take long.
    • Concurrent Server: The main process accepts incoming connections and immediately spawns a new child thread/process to handle that specific client, returning to listen on the main port. Enables serving thousands of concurrent clients.

2. World Wide Web (WWW) and HTTP (Ch. 26.1)

The World Wide Web is a distributed client-server information repository where documents (web pages) are linked together via Hyperlinks. A web client is called a Browser; a web server is called an HTTP Server.

2.1 Uniform Resource Locator (URL)

A standard identifier used to locate web resources: protocol://host:port/path?query#fragment

  • protocol: Transfer protocol (e.g., http, https).
  • host: Domain name or IP address of the server (e.g., www.example.com).
  • port: Optional port number (default 80 for HTTP, 443 for HTTPS).
  • path: Hierarchical location of the file on the server (e.g., /courses/cn/notes.html).

2.2 HTTP: Hypertext Transfer Protocol

HTTP is a stateless, application-level request-reply protocol running over TCP (Port 80).

  • Stateless Nature: The server maintains no memory of past client requests. If a client requests the same web page 10 times in a second, the server treats each request as a completely new transaction. State is preserved using Cookies (small state tokens stored on the client browser).
  • Non-Persistent vs Persistent HTTP:
    • Non-Persistent HTTP (HTTP/1.0): A brand new TCP connection is opened for every single object (HTML file, image, CSS script). Each object requires $2 \times \text{RTT} + \text{transmission time}$ ($1 \text{ RTT}$ for TCP handshake $+ 1 \text{ RTT}$ for HTTP request/response). Massive server overhead and latency.
    • Persistent HTTP (HTTP/1.1): The server leaves the TCP connection open after sending a response. Multiple subsequent requests and responses can be transferred over the same single TCP connection. Supports Pipelining (sending multiple requests back-to-back without waiting for previous replies).

2.3 HTTP Request and Response Messages

HTTP Request Message Format:

  • POST: Submits data (form input, file uploads) to be processed by the server. Not idempotent.
  • HEAD: Identical to GET, but server returns only the headers without the entity body (used to check file size or modification date).

3. File Transfer Protocol — FTP (Ch. 26.2)

FTP is the standard client-server protocol used for copying files from one host to another over TCP.

3.1 Two-Connection Architecture: Control vs Data Connection

Unlike HTTP which transfers commands and data over the same connection, FTP establishes two separate parallel TCP connections:

Connection Default Port Persistence Function & Characteristics
Control Connection Port 21 Persistent for entire session Transmits user credentials, navigation commands (USER, PASS, CWD), and 3-digit server status codes. Carries 7-bit ASCII control traffic (called Out-of-Band control).
Data Connection Port 20 (Active) or Dynamic (Passive) Non-Persistent (opens and closes per file) Transfers the actual raw file data or directory listings. A new data connection is opened whenever a file transfer is requested (RETR, STOR, LIST) and closed as soon as the file ends.

3.2 Active Mode vs Passive Mode

  • Active Mode (Traditional): Client connects to server Port 21 and tells the server its own client data port using the PORT command. The server initiates an outbound TCP connection from Port 20 back to the client's port.
    The Firewall Problem: Client-side firewalls and NAT routers block unsolicited incoming connections from the server!
  • Passive Mode (PASV — Modern Standard): The client sends the PASV command. The server opens an ephemeral high-numbered port (e.g., 50201) and informs the client. The client initiates both the control and data connections, bypassing client firewall blocks completely!

4. Electronic Mail: SMTP, MIME, POP3, and IMAP4 (Ch. 26.3)

4.1 Email Architecture & Components

  • User Agent (UA): The software program used by the human to compose, read, and reply to messages (e.g., Thunderbird, Outlook, Gmail web app).
  • Mail Transfer Agent (MTA): Background server software that pushes email across the Internet from source server to destination server (e.g., Postfix, Sendmail, Exim).
  • Message Access Agent (MAA): Server software that authenticates users and delivers stored messages from the server mailbox to the client's User Agent (POP3, IMAP4).
  • Spool & Mailbox: The spool stores outgoing emails waiting to be dispatched; the mailbox holds incoming unread emails for that specific user.

4.2 Simple Mail Transfer Protocol (SMTP)

SMTP is a Push Protocol operating on TCP Port 25 (submission port 587).

  • Used to push emails from sender's UA to sender's mail server, and between intermediate mail servers across the Internet.
  • 7-Bit ASCII Limitation: SMTP was originally designed only for plain English text. It cannot transmit binary files, images, attachments, or non-English alphabets directly.

5. Domain Name System — DNS (Ch. 26.4)

Humans prefer intuitive textual domain names (www.google.com), but network routers require 32-bit (IPv4) or 128-bit (IPv6) numerical IP addresses. The Domain Name System (DNS) is a hierarchical, distributed database that translates domain names into IP addresses and vice versa, operating on UDP and TCP Port 53.

5.1 The Hierarchical Domain Name Space

  • Root Domain (.): The top of the tree, denoted by an unnamed string or dot.
  • Top-Level Domains (TLD):
    • Generic TLDs (gTLD): .com (commercial), .edu (education), .org (non-profit), .gov, .net.
    • Country-Code TLDs (ccTLD): .in (India), .uk (UK), .jp (Japan), .us.
  • Second-Level Domains: Assigned to organizations under a TLD (e.g., vtu.ac.in, google.com).
  • FQDN vs PQDN:
    • Fully Qualified Domain Name (FQDN): Ends with a dot, specifying full path from leaf to root (e.g., www.vtu.ac.in.).
    • Partially Qualified Domain Name (PQDN): Incomplete relative domain name (e.g., www or vtu).

5.2 Types of DNS Servers & Resolution

  • 1. Root Name Servers: 13 logical root server addresses (named [a-m].root-servers.net), replicated worldwide using anycast routing. They know the addresses of all TLD servers.
  • 2. TLD Name Servers: Responsible for specific TLDs (e.g., all .com or .in domains). Direct queries to authoritative servers.
  • 3. Authoritative Name Servers: Maintained by organizations or DNS hosting providers; holds the definitive master records for that domain. Divided into Primary (Master) and Secondary (Slave) servers for fault tolerance.
  • 4. Local DNS Resolver: Maintained by your ISP or campus. Intercepts client queries, checks local cache, and navigates the global hierarchy on the client's behalf.

6. TELNET & Secure Shell — SSH (Ch. 26.5 & 26.6)

6.1 TELNET (Teletype Network)

TELNET is a legacy client-server application developed in 1969 to allow a user on a local computer to log into and execute commands on a remote computer across TCP Port 23.

  • Network Virtual Terminal (NVT): To enable heterogeneous terminals to communicate with different operating systems, TELNET invented the NVT. The client translates local keystrokes into standard NVT characters; the server converts NVT characters into the host operating system's internal character format.
  • Command Embedding: Uses a special escape byte called IAC (Interpret As Command — byte value 255 / 0xFF) to send out-of-band signals (e.g., interrupt process, suspend).
  • Fatal Flaw — Complete Lack of Security: TELNET transmits all data in plaintext — including user passwords and root terminal commands. Any eavesdropper running a packet sniffer (Wireshark) on the local network or public Wi-Fi can capture usernames and passwords in clear text!

6.2 Secure Shell (SSH)

SSH was designed as a cryptographically secure, encrypted replacement for TELNET, rlogin, and FTP. Operates over TCP Port 22.

SSH Three-Layer Architecture:

  1. SSH Transport Layer Protocol: Establishes a secure, confidential communication channel over an insecure network. Handles:
    • Server Authentication: Server proves its identity using host public keys (preventing man-in-the-middle attacks).
    • Key Exchange: Uses Diffie-Hellman to negotiate a shared session key without transmitting it over the wire.
    • Symmetric Encryption: Encrypts all data payload (AES, ChaCha20).
    • Data Integrity: Every packet includes an HMAC (Hash-based Message Authentication Code) to prevent packet tampering.
  2. SSH User Authentication Protocol: Runs on top of the transport layer to authenticate the human client to the server:
    • Password Authentication: Transmitted securely inside the encrypted channel.
    • Public-Key Authentication: Client generates an asymmetric key pair (RSA or Ed25519). The public key is stored in the server's ~/.ssh/authorized_keys. The client proves ownership of the private key via digital signature challenge — eliminates passwords entirely!
  3. SSH Connection Protocol: Multiplexes multiple logical communication channels over the single encrypted connection:
    • Interactive terminal shell sessions.
    • Remote single-command execution.
    • Secure file transfer (SFTP, SCP).
    • Port Forwarding / SSH Tunneling:
      • Local Port Forwarding (ssh -L): Forwards a port from client PC through the encrypted SSH tunnel to a private server inside a firewall.
      • Remote Port Forwarding (ssh -R): Forwards a port on the remote server back to a local development machine.
